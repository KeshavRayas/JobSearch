The change map

Green and red are a review layer over the document, not a new resume style. The final document and PDF stay clean.

Green — added or rewritten

Text produced by tailoring for this job, or rewritten from a cited base-resume item. Hover shows the source count and opens “revert this change”.

Red — removed from base

Base-resume text that the model removed or replaced. Visible only in Changes mode; hidden in Final and never rendered into the PDF.

Plain — unchanged

Facts and bullets kept from the base resume. Company, dates, school, project names, and skills are enriched from the base; the model only rewrites prose.

Full flow

Same loop as Tsenta: queue, tailor, review, approve, apply. No autofill and no background submission.

user action loop / state changeNo autofill. No background submission.

Implementation plan

Small enough to ship without changing the evidence rules or the PDF pipeline.

01

New full-screen route

/apply/[id] loads the job, analysis, current draft, and profile on the server. A client ApplyWorkspace owns the queue, edit state, diff toggle, and approval.

  • Extract the document + editor from JobDetailPanel.
  • Keep the modal for job facts and a “Review application” CTA.
  • Preserve Calm Focus: hairlines, serif display, no new chrome.
02

Change map

Compare each tailored field to the cited base item. Word-level LCS for prose; whole-bullet for arrays. Green for added/rewritten, red for removed. “Final” hides red and clears green.

  • Highlights are UI-only; ResumeDocument and Typst never receive them.
  • Hover a change → source count, “revert this change”.
  • Ignore whitespace and punctuation-only moves to reduce noise.
03

Revert + versions

POST /api/jobs/:id/revert creates a new version from the base resume. A per-field revert restores that field from the cited base item. Both set status back to DRAFT.

  • Keep the previous version in history.
  • Approval is always explicit after a revert or re-tailor.
  • Never mutate JobMatch.score.
04

Manual apply handoff

Approve unlocks “Open application”. Opening records OPENED and opens the company page in a new tab. “I’ve applied” records APPLIED.

  • No form filling, logins, OTPs, or browser automation.
  • Disable opening until the current version is approved.
  • Keep “Check live” on the job card.
Risks

Word-level diffs can look noisy on heavily rewritten bullets. Mitigation: default to block-level for bullets, word-level for summary; offer “only changed lines”. Long resumes need a scrollable paper pane with the action bar fixed. Mobile collapses the queue and fit into drawers.

Acceptance

The resume gets at least 60% of a 1440px viewport. A first-time user can queue a job, see fit, edit text, revert one change, approve, open the company page, and mark applied without returning to the modal. The PDF contains no green/red or diff annotations.
